# locals-ios

Native Swift / SwiftUI iOS app for [Locals](https://locals.ecodia.au) - a national network of independent Australian businesses, customers free always, merchants pay what they want.

Part of the three-native-codebases pattern: [locals-web](../locals-web) + [locals-ios](.) + locals-android, each consuming the shared [locals-shared](../locals-shared) substrate (design tokens, Supabase schema, edge functions).

## Stack

- Swift 5.10 / SwiftUI / iOS 17.0+
- XcodeGen (project.yml is the source of truth, `Locals.xcodeproj` is generated)
- [Supabase Swift](https://github.com/supabase/supabase-swift) for auth + PostgREST + Storage
- [Nuke](https://github.com/kean/Nuke) for image loading + cache
- MapKit (native) for Discover - clustering, look around, user location dot, all native
- CoreLocation for "near you"
- AuthenticationServices for Sign in with Apple (magic link is the fallback)
- SafariServices for the Stripe Checkout redirect (Apple 2024 reader pattern)

No third-party UI framework. No React Native. No Capacitor. Native screens, native typography, native haptics.

## Three-native-codebases discipline

- **Things that must be identical across web + iOS + Android** live in [`../locals-shared`](../locals-shared): design tokens, Supabase migrations, Supabase edge functions.
- **Things that are platform-specific** live in the platform repo. A SwiftUI view modifier is iOS-only. A Tailwind config is web-only. A Compose composable is Android-only. That is fine.
- When tokens or schema change in locals-shared, every platform re-generates its representation: `scripts/sync-tokens.sh` here, `pnpm sync:tokens` on web, gradle on Android.

## Build locally

```bash
# install xcodegen once
brew install xcodegen

# regenerate the Xcode project from project.yml
xcodegen generate

# open in Xcode
open Locals.xcodeproj

# or build from the command line
xcodebuild -project Locals.xcodeproj -scheme Locals -configuration Debug \
  -destination "platform=iOS Simulator,name=iPhone 15 Pro" build
```
